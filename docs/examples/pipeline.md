# Pipeline examples

These examples focus on when pipeline tasks are a better fit than calling layout
operations directly. The examples use the same rule throughout: typed tasks work
within one subject type, while handover tasks move data between typed subjects.

## Example workspace

```go
type ServiceConfig struct {
	Name    string   `json:"name"`
	Port    int      `json:"port"`
	Routes  []string `json:"routes"`
	Enabled bool     `json:"enabled"`
}

type Service struct {
	Root   layout.Dir                         `layout:"."`
	Config formats.JSONFile[ServiceConfig]    `layout:"config.json"`
}

type ServerConfig struct {
	Service string `json:"service"`
	Port    int    `json:"port"`
}

type Server struct {
	Root   layout.Dir                      `layout:"."`
	Config formats.JSONFile[ServerConfig]  `layout:"config.json"`
}

type Route struct {
	Service string `json:"service"`
	Path    string `json:"path"`
}

type Sitemap struct {
	Routes []string `json:"routes"`
}

type Workspace struct {
	Root     layout.Dir                               `layout:"."`
	Services layout.Slot[*Service]                    `layout:"services"`
	Servers  layout.Slot[*Server]                     `layout:"servers"`
	Routes   layout.FileSlot[formats.JSONFile[Route]] `layout:"routes"`
	Artifacts layout.FileSlot[formats.JSONFile[Sitemap]] `layout:"artifacts"`
}
```

Why pointer slots are used here:

- ordered pipeline tasks share layout references instead of passing hidden outputs
- pointer slot items make in-memory edits visible through later slot snapshots
- persistence is still explicit through `SyncDeep`

## Format byte files in place

Goal: apply the same byte transform to several layout files and write each file
back only after every source has transformed successfully.

```go
p := pipeline.New(
	pipeline.TaskFromFiles("format", generatedFiles...).
		Transform(layout.DefaultContext, gofmtTransform).
		WriteBack(layout.DefaultContext),
)

_, _ = p.Run(context.Background(), pipeline.RunOptions{Context: pipeline.DefaultContext})
```

Why pipeline fits:

- each file stays a byte subject
- transform output is buffered before any writeback
- one task can fail before touching the destination files

## Split generated bytes into a directory

Goal: take one generated byte payload, split it into several files, and shape the
output paths explicitly.

```go
func splitSections(ctx context.Context, lctx layout.Context, split pipeline.Split, item pipeline.Item[pipeline.Blob]) error {
	data, err := split.Read()
	if err != nil {
		return err
	}

	for i, section := range bytes.Split(data, []byte("\n---\n")) {
		split.EmitBytes(fmt.Sprintf("section-%02d.txt", i), section)
	}
	return nil
}

p := pipeline.New(
	pipeline.TaskFromBlob("manual", pipeline.Blob{Name: "manual.txt", Data: generated}).
		Split(layout.DefaultContext, splitSections).
		ToDir(layout.DefaultContext, docsDir, pipeline.Flatten()),
)
```

Why the destination option matters:

- `Flatten` writes every emitted item by basename under `docsDir`
- `PreserveStructure` would keep each item's relative path
- unsafe paths are rejected during planning before bytes are written

## Process typed services

Goal: update typed service configs in memory, then sync only the services that
were already cached in the slot.

```go
p := pipeline.New(
	pipeline.TaskFromSlotEntries("enable-services", &ws.Services).
		Filter(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, item pipeline.Item[*Service]) (bool, error) {
			cfg := item.Value.Config.MustGet()
			return cfg.Enabled, nil
		}).
		Process(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, item pipeline.Item[*Service]) (*Service, error) {
			cfg := item.Value.Config.MustGet()
			cfg.Port = cfg.Port + 1000
			item.Value.Config.Set(cfg)
			return item.Value, nil
		}).
		SyncDeep(layout.DefaultContext),
)
```

Why this stays a typed task:

- every step is still about `*Service`
- `Process` changes `T -> T`
- `SyncDeep` persists the service layout only after the typed work is complete

## Bridge services into servers

Goal: derive one server entry from each service entry while keeping persistence
explicit.

```go
p := pipeline.New(
	pipeline.TaskFromSlotEntries("normalize-services", &ws.Services).
		Process(layout.DefaultContext, normalizeService).
		DefaultDeep(),

	pipeline.Bridge("configure-servers",
		pipeline.SlotEntries(&ws.Services),
		pipeline.SlotEntries(&ws.Servers),
	).
		Populate(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, service pipeline.Item[*Service], server *pipeline.Item[*Server]) error {
			cfg := service.Value.Config.MustGet()
			server.Value.Config.Set(ServerConfig{
				Service: cfg.Name,
				Port:    cfg.Port,
			})
			return nil
		}).
		EnsureDeep(layout.DefaultContext).
		SyncDeep(layout.DefaultContext),
)
```

Why `Bridge` fits:

- the origin and target are both slot entry sets
- default target keys reuse `service.Key`
- `Populate` owns the domain mapping from service state to server state
- `EnsureDeep` and `SyncDeep` make the write explicit

`Populate` is required. It appears after any origin `Filter`, `Sort`, or `Rekey`
so the chain reads in the same order the task executes.

## Bridge with rekeying

Goal: keep one server per service, but use environment-specific target keys.

```go
p := pipeline.New(
	pipeline.Bridge("configure-prod-servers",
		pipeline.SlotEntries(&ws.Services),
		pipeline.SlotEntries(&prod.Servers),
	).
		Rekey(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, service pipeline.Item[*Service]) (string, error) {
			return "prod-" + service.Key, nil
		}).
		Populate(layout.DefaultContext, populateServer).
		EnsureDeep(layout.DefaultContext).
		SyncDeep(layout.DefaultContext),
)
```

Duplicate target keys follow `pipeline.Context.DuplicateOutputs`:

- `DuplicateOutputFail` rejects duplicates before target mutation
- `DuplicateOutputLastWins` keeps only the final origin for each target key

## Compile services into one artifact

Goal: build one generated JSON artifact from many service entries.

```go
p := pipeline.New(
	pipeline.Compile("sitemap",
		pipeline.SlotEntries(&ws.Services),
		pipeline.FileSlotEntry(&ws.Artifacts, "sitemap.json"),
	).
		Filter(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, service pipeline.Item[*Service]) (bool, error) {
			cfg := service.Value.Config.MustGet()
			return cfg.Enabled, nil
		}).
		Sort(func(a, b pipeline.Item[*Service]) bool { return a.Key < b.Key }).
		Build(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, services []pipeline.Item[*Service], target *pipeline.Item[formats.JSONFile[Sitemap]]) error {
			var sitemap Sitemap
			for _, service := range services {
				cfg := service.Value.Config.MustGet()
				for _, route := range cfg.Routes {
					sitemap.Routes = append(sitemap.Routes, "/"+cfg.Name+route)
				}
			}
			target.Value.Set(sitemap)
			return nil
		}).
		EnsureDeep(layout.DefaultContext).
		SyncDeep(layout.DefaultContext),
)
```

Why `Compile` fits:

- the source is many service entries
- the target is one fixed file-slot entry
- `Build` sees the filtered and sorted origin slice
- the generated artifact still uses the typed file lifecycle

`Build` is required and runs after origin filtering and sorting.

## Expand services into route files

Goal: extract multiple route files from each service entry.

```go
p := pipeline.New(
	pipeline.Expand("routes",
		pipeline.SlotEntries(&ws.Services),
		pipeline.FileSlotEntries(&ws.Routes),
	).
		Extract(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, service pipeline.Item[*Service], emit pipeline.EntryEmitter[formats.JSONFile[Route]]) error {
			cfg := service.Value.Config.MustGet()
			for _, routePath := range cfg.Routes {
				key := cfg.Name + strings.ReplaceAll(routePath, "/", "-") + ".json"
				emit.Emit(key, func(target *pipeline.Item[formats.JSONFile[Route]]) error {
					target.Value.Set(Route{Service: cfg.Name, Path: routePath})
					return nil
				})
			}
			return nil
		}).
		EnsureDeep(layout.DefaultContext).
		SyncDeep(layout.DefaultContext),
)
```

Why `Expand` fits:

- each origin can emit zero or more targets
- emitted keys define the target file-slot entries
- duplicate emitted keys are handled before target population according to the
  pipeline duplicate policy

`Extract` is required and runs after origin filtering and sorting.

## Keep handover memory-only

Goal: populate target slot caches for a later task without writing them yet.

```go
p := pipeline.New(
	pipeline.Bridge("preview-servers",
		pipeline.SlotEntries(&ws.Services),
		pipeline.SlotEntries(&preview.Servers),
	).
		Populate(layout.DefaultContext, populateServer),

	pipeline.TaskFromSlotEntries("inspect-preview", &preview.Servers).
		Process(layout.DefaultContext, inspectServer).
		ValidateDeep(layout.ValidateOptions{}),
)
```

Why this is useful:

- handover tasks update target slot caches in memory
- they do not create directories or write files unless deep operations are added
- a later task can inspect or validate the populated target references

## Produce byte artifacts for later tasks

Goal: derive byte artifacts from typed entries, then hand them to a later byte
task before choosing the final destination.

```go
routes := pipeline.BlobSubjects()

p := pipeline.New(
	pipeline.ExpandToFiles("routes",
		pipeline.SlotEntries(&ws.Services),
		routes,
	).
		Extract(layout.DefaultContext, func(ctx context.Context, lctx layout.Context, service pipeline.Item[*Service], emit pipeline.EntryEmitter[pipeline.Blob]) error {
			cfg := service.Value.Config.MustGet()
			for _, routePath := range cfg.Routes {
				key := cfg.Name + strings.ReplaceAll(routePath, "/", "-") + ".json"
				emit.Emit(key, func(target *pipeline.Item[pipeline.Blob]) error {
					target.Path = filepath.Join(cfg.Name, key)
					target.Data = mustJSON(Route{Service: cfg.Name, Path: routePath})
					return nil
				})
			}
			return nil
		}),

	pipeline.TaskFromBlobSubjectSet("pretty-routes", routes).
		Transform(layout.DefaultContext, prettyJSON).
		ToDir(layout.DefaultContext, ws.Output, pipeline.PreserveStructure()),
)
```

Why `ExpandToFiles` fits:

- origins are still typed slot entries
- produced targets are bytes, not typed file-slot entries
- the extracted blobs stay available in memory for later byte tasks
- final persistence still uses explicit byte-task sink semantics
